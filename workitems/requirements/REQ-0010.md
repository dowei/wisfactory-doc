名称：采集通道管理（MQTT/HTTP 与协议类型预留）
所属模块：管理系统（Java）
目标角色：集成工程师
优先级：P0
业务目标：回答点位「从哪条通道进来」；通道类型与地址字段预留使后续加协议平台侧零改动。
业务能力：通道 CRUD（所属网关下编码网关内唯一、名称、协议类型〔MQTT/HTTP/MODBUS/OPCUA 字典〕、连接配置 JSON〔MQTT 含 broker/topic/QoS，HTTP 含上报路径与鉴权方式；Modbus/OPC UA 二期定义、结构由 Schema 约束〕、状态）；一期只实现 MQTT、HTTP 两种通道运行逻辑，MODBUS/OPCUA 通道可建不可启用；通道变更后须重新发布才生效（保存≠生效）。
核心规则：通道凭据不入 conn_config 明文（独立存 REQ-0011，ADR-0006）；删除通道时其下有点位则拒绝；conn_config 结构由配置 JSON Schema 约束，数据库层不拆列；一期通道管理做轻——不做通用协议抽象 CRUD（归适配器框架 REQ-0012）。
非目标：不做 Modbus/OPC UA 适配器实现（二期）；不做通用协议插件机制；下发控制。
验收标准：1. 建 MQTT 通道并关联网关后，该通道下点位上报可经配置快照入库；2. 通道类型可选 Modbus/OPC UA，保存成功但标记未启用适配器，一期不产生接入行为；3. HTTP 端点同一点位同一时间戳重复上报只入库一次；4. 通道变更未经发布对接入不生效，发布后生效。
原始来源：MQTT 网关、智能仪表、边缘设备主动上报——一期核心通道，按主题区分工厂 / 网关，支持断线重连与补传；HTTP 第三方系统推送、人工补录、老系统对接——提供标准上报接口，带鉴权与幂等。
来源：工厂数据采集系统产品设计文档 §3.2；工厂数据采集系统详细设计（数据库与接口） §1.3、§3.1
