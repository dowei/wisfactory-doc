名称：MQTT/HTTP 采集接入与统一落库
所属模块：采集接入（Go）
目标角色：系统自动触发（网关/第三方上报）；运维经死信与监控观察
优先级：P0
业务目标：「采进来」主线——接入层与协议无关：校验、去重、量程标记、批量写入、触发计算；新增协议时这一层零改动；接入幂等是可靠性三支柱之一。
业务能力：MQTT 消费（data/status/config/LWT 四主题，QoS1）+ HTTP /ingest/v1/report 同构上报，同一流水线同构结果；处理顺序固定：验令牌与租户→按 pointCode 查配置快照（本地缓存）→未知编码进死信计数告警不落库→质量判定→按 data_type 分发写 st_point_num/st_point_state（ADR-0001）+更新 Redis 点位缓存；入库前校验流水线（格式校验〔编码存在、类型匹配，不合格进异常队列告警不静默丢弃〕、量程校验〔超限打码 1/2 不丢弃〕、时间校验、去重）；EMQX 认证回调 /ingest/v1/auth/mqtt（allow/deny+主题范围限定，只能收自己的 config 只能发自己的 data/status）；LWT 离线置状态并告警事件；攒批写入（100-500 条或 200ms，禁止逐条写库）。
核心规则：消息只认 pointCode 不认 id；ts 为设备侧采样时间与 sentAt 分开，迟到数据按 ts 落库；幂等键 (pointCode, ts)，batchId 整批幂等；单消息 points≤500 超限拆包；一条硬规则：任何情况下都不用 0 或上一个值填补缺失；时间校验纠偏口径（TD-0016 已裁决，ADR-0009）：补传/迟到消息豁免纠偏，纠偏仅对超出补传窗口的异常时间戳生效并打标记；人工补录口径（TD-0048 已裁决，ADR-0009）：人工补录/修正改走管理面接口（质量码 5、记操作审计），ingest 通道收敛为纯机器上报、统一消息模型不增加来源字段；JUMP 突变检测一期默认关闭（TD-0017 已裁决，ADR-0010）：NaN/类型异常为必做项，跳变检测与阈值配置预留二期、待试点真实数据标定后开启——避免设备启停正常跳变刷出假异常；码位 8（突变待核查）按 CONV-02 扩位预留，检测与码位分离；LWT 离线状态走事件链路（TD-0049 已裁决，ADR-0010）：接入服务只发离线事件、不直写 Redis 状态，最终状态由计算引擎按状态判定优先级链裁决落 Redis——守「按写入方划分」纪律，离线只是状态判定规则的一个输入。
非目标：不做告警闭环（三期）；不做协议直连采集；接入服务不做公式计算（只发新值事件）；接入服务永不直查业务库取配置（只读账号仅灾备核对）；接入调试页一期不做、整体二期（TD-0018 → ADR-0012，已登记 phase2-backlog PB-02）。
补传链路确认语义（ADR-0013 增补 1）：网关本地缓存经平台确认接收（ACK）后才删除，未确认前重发由接入幂等兜底；补传限速参数可配；幂等键 (pointCode, ts) 与 batchId 确认纳入统一消息模型冻结契约（TD-0046 冻结门内确认项）。
验收标准：1. 同一点位数据的 MQTT 报文与 HTTP 上报走同一流水线产出一致结果（同超级表、同质量码、同缓存值）；2. 未知编码进死信计数告警不落库；3. 同点位同时间戳并发两条只入库一条；batchId 整批重复只落一次；单消息>500 整批拒绝；4. 超上限值入库且 quality=1、原值不丢；断线恢复后库中无中间周期 0/旧值填充；5. 非法客户端 deny、合法客户端越权主题发布被拒；6. 攒批落库（无逐条写）、配置走本地缓存（无每消息查关系库）。
原始来源：接入处理顺序固定为：验令牌与租戶 → 按 pointCode 查配置快照（本地缓存）→ 未知编码进死信计数并告警、不落库 → 质量判定 → 按 data_type 分发写 st_point_num / st_point_state + 更新 Redis 点位缓存。／一条硬规则：任何情况下都不用 0 或上一个值去填补缺失。
