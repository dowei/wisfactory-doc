名称：租户管理与多租户框架改造
所属模块：管理系统（Java）
目标角色：平台运营方（私有化下即驻场运维）、租户管理员
优先级：P0
业务目标：同一套代码同时支撑云端多租户与私有化单租户（租户数=1），禁止为私有化分叉单租户版本；tenant_id 全链路透传是多租户隔离的根。
业务能力：sys_tenant 租户主数据维护（编码全局唯一且创建后不可改、承载点位/存储/有效期）；基础框架 sys_user / sys_dept / sys_role 系补 tenant_id（登录先定租户再查用户，sys_menu / sys_module 平台级不加）；租户级配额（点位数量上限、存储用量统计与告警、接入吞吐上限）；租户开通触发 TDengine 建库（库名 iot_<tenant_code>，只由 tenant_code 派生）。
核心规则：tenant_id 由登录态/调用上下文注入，禁止前端传参指定；所有配置查询强制带租户条件；到期只告警与禁新增、不删数据；禁用租户后登录、采集上报、对外 API 三条入口全部拒绝；私有化初始化一个默认租户（tenant_code 固定），行为与单租户系统无异。
非目标：不做租户计费/订单；不做租户自助注册开户（一期运营方手工开户）；不做跨租户数据迁移工具；不做弹性扩容自动化。
验收标准：1. 运营方新建租户并初始化管理员后，该管理员可登录且只见本租户数据；2. 相同用户名在两个租户可并存互不串号（(tenant_id, username) 联合唯一）；3. 私有化单租户包不改代码直接以多租户模式启动，云端扩租户不改代码不改表结构；4. 租户开通后 iot_<tenant_code> 库自动创建；5. 点位数达配额上限后新增被拒并明确提示（配额触顶行为细节见 TD-0035、吞吐超限行为见 TD-0041）。
原始来源：租户 = 企业 / 集团。一个集团及其下属全部工厂是一个租戶；不同集团之间是不同租戶，数据、配置、用戶完全隔离。／资源层（租戶级配额：点位数量上限、接入吞吐上限、存储用量统计与告警；单租戶补传风暴或公式死循环不得耗尽全平台资源）
