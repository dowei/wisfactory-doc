编号：ADR-0006
名称：通道凭据密文存储与单独下发方案
状态：已接受
创建时间：2026-11-21 03:05:56
创建者：coordinator
日期：2026-11-21
背景：详细设计 V1.0 §1.3 iot_channel 注明「通道的设备令牌等凭据不入 conn_config 明文，凭据经框架的凭据管理下发，表中只存引用标识」；经实测核查 01_base.sql，全库无凭据/credential 相关表与功能（零命中），框架仅有 SM4 加解密工具（sys_user 的 email/phone 在用，{v1} 密文格式）。详细设计该句悬空，凭据落地方案缺失。
候选方案：A 新建 iot_channel_credential 表，SM4 密文存储 + 密钥不入库 + 独立通道下发；B 凭据随配置快照明文下发；C 引入外部密钥管理服务（Vault/KMS 类）。
决定：A——新建 iot_channel_credential 表：凭据以 SM4 密文存储（复用框架 {v1} 加密约定）；密钥不入库，走环境变量/密钥服务；凭据不进配置快照明文，下发走 HTTPS + 网关令牌单独拉取、内存解密；凭据读取接口单设权限并记操作日志。
理由：与框架敏感字段处理思路一致（sys_user 敏感字段 SM4 密文 + 检索指纹、iot_api_client 密钥只存哈希），不自立规范。方案 B 被放弃：明文进快照会把凭据扩散到全部下游缓存、日志与中台，且快照哈希校验机制反而固化了明文副本。方案 C 被放弃：一期组件过载，违背架构选型「组件能晚引入就晚引入」原则；接口上预留密钥服务替换位即可。
影响范围与副作用：MySQL 设计增 1 张表；配置快照 Schema 明确不含凭据字段；网关配置同步流程增加「凭据单独拉取」步骤（网关令牌鉴权）；权限标识新增（如 iot:channel:credential）；凭据读取全量记操作日志；后续 TC 覆盖「快照与日志中无凭据明文」用例。
关联对象：后续 FEAT（通道管理、配置同步）引用本 ADR；与 CONV「敏感数据不落明文」口径一致。
