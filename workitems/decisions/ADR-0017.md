名称：组织节点作为数据项与指标配置主体的五项裁决
日期：2026-11-26
背景：用户需求要求工厂/车间/产线（node_type 1/2/3）也能像设备一样套用模板、拥有自己的数据项与指标（全厂/全车间电量、按车间计算的指标），且模板带入数据仅作初始基线、实例可增删改。现有模型口径是「组织节点无模板零生成、无数据项」「数据项唯一写入源是模板生成（只增不改不删）」「指标无 nodeType 限制但界面无组织节点入口」。四项初始口径加一项核实增补需定版才能拆解实现。
候选方案：①组织节点模板升级——A 与设备一致纳入待升级链 / B 仅首次生成基线不跟升级；②数据项来源——A 复用现有 1绑定/2公式/3汇总并扩展公式引用范围 / B 新增 source_type=4 组织级聚合；③界面承载——A 实例右侧加数据项/指标两个 Tab / B 打开独立详情抽屉；④模板基线与实例改动的关系——A 严格维护「只增不改不删」，重生成只补缺失项、实例增删改项永久保留（模板删项也保留） / B 重生成时按模板反向删除实例自造项（更"干净"但会吞掉实例配置），/ C 给组织节点另起一套生成语义（分叉）；⑤事后套模板——A 保持 templateId 不可变、不提供套用入口 / B 放开不可变、新增套用端点。
决定：①选 A——组织节点模板纳入待升级链，与设备同口径；②选 A——复用三种 source_type，扩展公式引用范围（组织级引用本组织数据项/指标、跨层按 full_key 解析，循环与存在性后端校验）；③选 A——实例管理页点击组织节点后右侧在现有下级节点列表之外增加「数据项」「指标」两个 Tab；④选 A——维持「只增不改不删」语义，重生成仅补缺失项，实例层对数据项/指标的增删改（含模板带入项被改造）均被保留，模板删除项也不反向删除实例项。四项由人类第①②③决策与最小改动原则④裁决。
增补裁决（2026-11-26，计划评审核实后）：
- ①落地方式修正：核实生成链 `generateForInstance` 与待升级链 `selectUpgradeList` 均按 templateId 判定、不按 nodeType 过滤——组织节点新建时选模板即自动纳入待升级、自动按模板生成数据项，第①项无需新增代码，降级为「验证既有能力 + 文档明确」。
- ⑤选 A：templateId 保持创建后不可变（`IotModelInstanceServiceImpl.validateImmutability` 明确拒绝改 templateId），不提供已建组织节点事后套用/变更模板入口；前端实例表单对 node_type 1/2/3 模板下拉已支持（非必填）。已建组织节点（如冒烟工厂T12）通过「实例级增删数据项/指标」（裁决②④）补齐数据。理由：放开 templateId 会动摇 full_key 前缀/父子关系稳定性等核心不变量（TD-0010 一期禁止挪树同类理由），且用户核心诉求「给已建工厂绑数据」可由实例级增删改满足，无需改模板绑定。
理由：①选 A 保持模板变更链路统一，避免组织节点成为升级盲区（人类明确选择与设备一致）；②选 B 会动枚举、前端、计算引擎与契约，而全厂/全车间电量可由「绑定点位」（全厂电表直连）与「公式引用下级数据项/指标」覆盖，复用现有三态即可，成本显著更低（人类选择复用扩展）；③选 A 与用户建议一致且不必新开页面层级（人类选择）；④选 A 遵循既有重生成「历史不删」不变量——反向删除会破坏配置审计（iot_data_item_history）与已发布引用，且模板删项的本意是"不再新增"而非"强制回收"，分叉语义则让两套生成逻辑长期漂移；⑤选 A 守住 templateId 不可变核心不变量、以实例级增删改满足诉求，避免为事后套模板引入 full_key 前缀漂移风险。
影响范围与副作用：REQ-0036 / FEAT-0022 按五项裁决实现；生成链与待升级链经核实已按 templateId 判定、不按 nodeType 过滤，组织节点新建选模板即自动覆盖，无需改造（TASK-0099 降级为验证性任务）；数据项服务端需新增实例级增删接口（TASK-0100）；指标服务端已无 nodeType 限制但需契约明确组织节点合法（TASK-0101）；公式/引用校验扩展组织级解析（TASK-0101）；templateId 保持不可变、不提供事后套模板入口（裁决⑤）；前端实例页加 Tab、数据项/指标 CRUD 复用 0094/0095 已建组件（TASK-0102）；FEAT-0004/0012/0014/0019 的关联口径需在本 ADR 留下演进指针，不删旧对象。副作用：组织级 full_key（F01.XXX）与设备级共存，展示端需区分标注避免重复计数；组织级数据项若绑定点位需全厂/全车间电表，点位建档责任在点位管理页；已建无模板组织节点只能靠实例级增删数据项补齐、无法事后套模板（呈报人类把关项）。
