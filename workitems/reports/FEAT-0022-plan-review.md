3. **6 边界（越权、超限）**：出处 TASK-0100 `验收标准`、TASK-0101 `验收标准`、TC-0028 步骤 6~7、TC-0029 步骤 8~9；两类边界在 TASK 与 TC 中均打到且判据可观察。
4. **10 TC 形态**：出处 TC-0027 / TC-0028 / TC-0029 步骤 1 与各预期结果；执行方式已写明、判据可观察、未逐条文档化单测断言，符合清单口径。

### 可自决修改
1. 【覆盖 / TC】出处 TC-0027 步骤 3、TC-0028 步骤 3、REQ-0036 验收标准 4：组织级 full_key 与设备级不冲突无 TC 步骤比对；补一条两层级 full_key 共存且不冲突的观察步骤即可。
2. 【覆盖 / TC】出处 TC-0028 `用例描述` 与步骤 2~7、TASK-0102 `验收标准`：「删除指标」「改数据项公式/汇总/绑定点位/阈值」无步骤或验收落点（TASK-0102 只写指标「增改」）；补步骤与验收词。
3. 【覆盖】出处 FEAT-0022 `功能项与字段`（node_type 1/2/3）与 TC-0027 / 0028 / 0029 `测试数据`：产线（node_type=3）无任何用例，三条 TC 只用工厂/车间；补一条 node_type=3 步骤或注明与 1/2 同口径不另测。
4. 【验收可判定】出处 TASK-0099 / 0100 / 0101 `验收命令`：三条 `mvn -q test` 只能判定「0 失败」，无法判定各自的组织节点特有业务标准；在验收命令或验收标准中写明新增测试类/方法名。
5. 【验收可判定】出处 TASK-0102 `验收命令`：「基线 713 例零回归」硬编码易过期，且四门未指定覆盖 Tab/权限/空态的新增用例；改为「既有测试零失败 + 新增 N 例」并写明用例范围。
6. 【验收可判定】出处 TASK-0103 `验收标准`（无遗留 Critical/Important）与 `验收命令`（命令见各 TC）：缺陷来源/分级判据未给、TC 内无具体命令；补缺陷登记位置与命令或改正措辞。
7. 【边界】出处 FEAT-0022 `异常与边界`「并发」类 vs TASK-0099~0103 `验收标准`、TC-0027~0029：并发打点缺失；补一条并发验收判据/TC 步骤，或明确「沿用现有乐观锁/唯一键、不另测」的判据。
8. 【边界】出处 FEAT-0022 `异常与边界`「空数据」类 vs TC-0027~0029：「无模板组织节点」空态只见 TASK-0102 验收标准一句、TC 无对应用例；补一条无模板空态步骤。
9. 【粒度】出处 TASK-0100 `涉及文件`/`实施步骤`（add + delete 两接口）、TASK-0102 `实施步骤`（Tab 框架 + 数据项 Tab + 指标 Tab + 四门）；建议拆为「新增接口」/「删除接口+引用保护」与「Tab 框架+数据项 Tab」/「指标 Tab+四门」，TASK-0099/0101 跨多目录可视执行反馈再拆。
10. 【覆盖】出处 FEAT-0022 `页面与操作`「组织节点套用/变更模板走模板管理页既有入口」与 TASK-0099 `验收标准`：必读材料未给该入口支持 node_type 1/2/3 的证据、也无 TASK 承接套用动作 → **无法判定**；先核实既有入口是否存在，存在则降为通过，不存在则升级为回炉（见下）。

### 计划缺陷（回炉）
- **无确定项**：从必读材料看，五项主体功能均有 TASK 承接、依赖图健康、验收与边界问题均为文档层可补，无需整体回炉。
- **条件项（当前标「无法判定」）**：出处 FEAT-0022 `页面与操作` 与 TASK-0099 `验收标准`「工厂/车间套模板后生成初始数据项」——若核实「模板管理页既有入口」不支持给已建组织节点套用/变更模板，则 TC-0027 步骤 2 不可执行，且 FEAT 功能项「template_id 可空→套用后非空」无实现 TASK，需新增 TASK 并重排依赖，构成回炉；若入口存在则并入「通过」。
