## 一、详细设计 V1.1 §4 数据权限拦截实现 —— 全文（第 27 页）

> 章节实际标题为「**4 数据权限拦截实现**」（目录页 p2 作「4 数据权限拦截实现：data_scope 到可见实例集合的翻译 27」）。本节起止：全文仅占第 27 页（第 3 节止于 p26，第 5 节起于 p28）。

### 4.0 原则（p27）

原则（产品设计已定）：权限拦截放在数据查询层统一实现成一个组件，管理面列表、展示端、数据服务内部查询都调它；只控菜单与页面等于没有权限 — 接口直调即可绕过。本节给出从登录用户到可见实例集合的完整翻译步骤，开发时照此实现并写进单元测试用例。

### 4.1 翻译步骤（登录用户 → 可见实例集合）（p27）

| 步 | 动作 | 实现要点 |
| --- | --- | --- |
| 1 | 取用户全部角色的 data_scope | 多角色并存时逐个求部门集合后取并集；含 data_scope=1（全部）的角色时直接标记全租户可见，跳过后续部门求解 |
| 2 | 逐 scope 求部门集合 | 全部：全集；本部门及下属：用户 dept_id + sys_dept 中 ancestors 含该 id 的全部部门；本部门：仅 dept_id；仅本人：空集（数据查询场景无可见实例，管理面列表场景改走 create_by 过滤）；自定义：查 sys_role_dept |
| 3 | 部门集合 → 实例集合 | 查 iot_model_instance 中 dept_id 命中部门集合的实例（通常是工厂/车间节点） |
| 4 | 展开子树 | 以命中实例的 ancestors 前缀匹配展开全部后代实例，得到可见实例 id 集合；集团用户（全部）即全租户实例 |
| 5 | 拼查询条件 | 数据项/指标/曲线查询：`instance_id IN (可见集合)`；点位查询：dept_id 命中部门集合 OR bound_instance_id IN (可见集合)；TDengine 查询把 instance_code/dept 标签条件一并下推 |
| 6 | 缓存与失效 | 可见集合按 (user_id, 角色版本) 缓存于 Redis，TTL 10 分钟；部门、角色、实例绑部门变更时主动失效相关缓存 |

### 4.2 三类调用方的差异（p27）

| 调用方 | 权限来源 | 拦截点 |
| --- | --- | --- |
| 管理面用户 | sys_role.data_scope + sys_dept | 管理系统与数据服务的查询组件（同一组件、同一口径，禁止两处各写一套） |
| 展示端用户 | 同上 | 展示端所有数据请求走数据服务，不直连 TDengine |
| 对外调用方（中台） | iot_api_client.scope（实例范围）+ tenant_id | 数据服务验签后先以 scope 裁剪，再走与上相同的子树展开与查询拼接 |

### 验收红线（p27，原文段落）

验收红线（写进任务单）：用工厂 A 的账号直接调用接口查工厂 B 的实例编码，必须返回 403 或空结果（按接口约定二选一并全组统一，推荐数据不存在类查询返回空、详情类返回 403）；用 scope 只含一厂的中台 appKey 拉全租户树，只返回一厂子树。此两条不过，权限任务不算完成。

### §4 的外围引用点（翻译逻辑在别处的落点，供 brief 对齐）

- p21 §3.1：以下各表权限列为 sys_menu.perms 标识；**未标注的查询类接口同样走第 4 节的数据权限过滤（列表只返回可见范围）**；写操作全部记框架操作日志。

## 二、与翻译逻辑直接相关的表结构段落摘要（§0.x / §1.x / 附录 A）

### 框架侧（非新表，来自 §0 与基础框架的衔接）

- **sys_dept**（p4 §0.1）：带 parent_id + ancestors 祖级路径（如 `0,1`）；数据权限的部门展开直接用 ancestors 做前缀匹配，不递归查库。
- **sys_role.data_scope / sys_role_dept**（p4 §0.2）：框架已实现五种 data_scope，sys_role_dept 存自定义范围的部门集合；翻译逻辑（第 4 节）完全建立在 data_scope 与 dept.ancestors 之上，不新增权限模型、不新增授权表。五种语义与部门集合求法（p4 表）：

| data_scope | 框架语义 | 在本系统中的部门集合求法 |
| --- | --- | --- |
| 1 | 全部 | 不做部门过滤（仍受 tenant_id 约束） |
| 2 | 本部门及下属 | 用户 dept_id 本身 + ancestors 包含该 id 的全部下级部门 |
| 3 | 本部门 | 仅用户 dept_id |
| 4 | 仅本人 | 部门集合为空集，改为按 create_by = 当前用户过滤（仅管理面列表适用；数据查询无「本人」语义时按无可见实例处理） |
| 5 | 自定义 | 查 sys_role_dept 取该角色配置的部门集合 |

  p4 顺序注意（原文）：框架实现是「1 全部、2 本部门及下属、3 本部门、4 仅本人、5 自定义」，与早期口头描述的顺序不同。开发时以 DataScopeEnum 与本表为准，多角色取并集（任一角色为全部则全部可见）。
- **sys_ 核心表租户改造**（p5 §0.3 改造三）：sys_dept 加 tenant_id，ancestors 路径不变（部门树按租户隔离，数据权限展开在租户内进行）；sys_role / sys_role_dept / sys_user_role / sys_role_menu 加 tenant_id **（或经主表间接隔离，评审时二选一并全库统一——PDF 未定版，推荐直接加字段）**。

### 业务侧新表（§1.x）

- **iot_model_instance**（p10 §1.5，DDL p31 附录 A）：一棵租户内模型树（工厂 > 车间 > 产线（可选）> 设备 > 组件）；**实例是数据权限的锚点：每个实例绑一个部门，用户的可见范围最终翻译为可见实例集合（第 4 节）**。关键字段：
  - `instance_code` varchar(96)：租户内唯一，路径式（F01、F01.WS01、F01.WS01.EQ001）；
  - `parent_id`：父实例 id，顶级为 0；
  - `ancestors` varchar(1000)：祖级路径，逗号分隔 id 列表，仿 sys_dept.ancestors；**子树展开靠它做前缀匹配**（p31 DDL 注释同义，索引 `idx_ancestors`）；
  - `dept_id`：绑定部门 id（sys_dept.id）——**数据权限命中的关键字段，工厂/车间级节点必填**（p31 DDL 注释「绑定部门 ID（数据权限锚点）」，列定义为 `DEFAULT NULL`，必填靠服务层校验）。
  - 唯一约束 `uk_tenant_instance_code (tenant_id, instance_code)`；索引 `idx_tenant_parent`、`idx_tenant_dept (tenant_id, dept_id)`、`idx_ancestors`。
- **iot_point**（p9 §1.4）：`bound_instance_id`（冗余归属实例 id，由绑定关系回填，用于按工厂统计点位数与**权限粗筛**，可空）；`dept_id`（绑定部门 id，**点位列表与原始数据查询的数据权限按此过滤**）；索引 `idx_tenant_dept (tenant_id, dept_id)`、`idx_tenant_instance (tenant_id, bound_instance_id)`。
- **iot_metric**（p15 §1.7）：`instance_id`（归属实例，必填）；`dept_id`（绑定部门 id，**指标查询的数据权限按此与实例双重过滤**）。
- **iot_api_client**（p18 §1.10）：`tenant_id`（调用方只能访问本租户数据）；`scope` json——授权模型范围：实例 id/编码数组（**含子树标记**）；**为空表示无任何数据权限，不是全部 — 默认拒绝**；配套 iot_api_call_log：403 类错误（含 scope 外访问）必须全量记录（p18、p26）。
- **表关系速览**（p18）：sys_dept 被 iot_model_instance、iot_point、iot_metric 以 dept_id 引用（无外键，服务层校验）；iot_model_instance 自关联树（parent_id / ancestors）。
- **TDengine 下推侧**（p19 §2.2）：st_point_num 超级表标签含 `tenant_id`、`point_code`、`kind(INSTANT/CUMUL)`、`instance_key`、`dept_id`（标签是子表级元数据，无逐行成本；ADR-002 补 tenant_id 标签见 p3 修订说明）。

## 三、关联工作项要点归纳

### FEAT-0002（features/FEAT-0002.md，部门数据权限拦截组件，P0，已确认）

- 登录用户→可见实例集合的统一翻译组件（六步）；管理面列表、展示端、数据服务内部查询同一组件同一口径；拦截点抽象为策略接口，预留单数据项粒度扩展位。
- 五种 data_scope 语义映射；缓存 key=(user_id, 角色版本) TTL 10 分钟；点位查询条件 dept_id 命中 OR bound_instance_id 命中。
- 业务规则：多角色并集、含全部直接全租户可见；仅本人=配置类按 create_by、时序按空集；**未绑部门资产仅租户管理员可见（fail-closed）**；无权节点树接口不返回。
- 异常与边界：越权=跨厂红线（数据类空、详情类 403）；并发=绑定变更主动失效；**超限=子树展开上限（ADR 留痕）**。
- 关联决策 ADR-0011、ADR-0013；无独立页面，绑定 UI 挂模型管理页（归 FEAT-0004）。

### REQ-0002（requirements/REQ-0002.md，部门数据权限拦截，P0，已确认）

- 业务目标：数据权限与菜单权限分离，查询层统一拦截；用户可见范围最终翻译为可见实例集合；TDengine 标签条件一并下推。
- 定版裁决（ADR-0011）：TD-0044 仅本人=仅配置类对象按 create_by 生效、时序/指标查询按空集；TD-0043 未绑部门资产仅租户管理员可见（fail-closed 安全默认）。
- 策略接口（ADR-0013 增补 4）：一期实现=部门范围→可见实例集，预留单数据项粒度扩展位，二期细化不改查询层结构。
- 验收 5 条：红线一（A 厂查 B 厂：数据不存在类空、详情类 403，各有 TC）；红线二（scope 外中台拉树只返回一厂子树）；五种 data_scope 各建账号验证（重点自定义并集、ancestors 前缀匹配）；改绑定/角色后权限即时生效（主动失效，TTL 仅兜底）；点位原始数据查询同受控。
- 非目标：不做字段级权限/列脱敏、不做权限规则引擎、不做租户间权限（归 REQ-0001）、不合并部门树与模型树。

### TC-0002（testcases/TC-0002.md，跨厂越权红线，P0，异常类，已确认）

- 前置：工厂 A、B 各建实例树并绑部门；工厂 A 厂长账号（本部门及以下）；工厂 B 设备 EQ001 及数据项；中台 appKey（scope 仅一厂）。
- 步骤覆盖：实例树不含 B 厂节点；B 厂设备历史曲线（列表类）返回空集；直调 B 厂设备详情 403；改绑定后立即查询即时生效（主动失效）；scope 外中台拉全租户树只返回一厂子树；A 厂长查 B 厂点位原始数据空/403。
- 执行方式：自动化（命令待集成测试套件建立后按模块登记，暂手工）。

### TASK-0005（tasks/TASK-0005.md，数据权限翻译组件（六步）实现，P0，已确认，预估 5）

- 六步翻译组件（data_scope 并集→部门集合→实例集合→ancestors 子树展开→拼查询条件→缓存），拦截点抽象为策略接口（预留单数据项粒度扩展位）。
- 技术要点：组件独立模块、管理面与数据服务同一 JAR 引用；TDengine 查询 instance_code/dept 标签条件下推；ancestors 前缀匹配不递归查库。
- 实施步骤：1 策略接口与六步实现；2 查询条件拼装（MySQL+TDengine 下推）；3 单测覆盖五种 data_scope。前置任务：TASK-0002。
- 验收：五种 data_scope 可见集合正确；多角色并集；含全部直接全租户可见。验收命令：backend 单测（工程初始化后回填）。

### TASK-0006（tasks/TASK-0006.md，可见集合 Redis 缓存与主动失效，P0，已确认，预估 2，前置=TASK-0005）

- 可见集合按 (user_id, 角色版本) 缓存 Redis TTL 10 分钟；部门/角色/实例绑部门变更时主动失效相关缓存。
- 技术要点：失效事件由部门/角色/绑定变更点发布（Spring 事件或 Redis pub/sub）；TTL 仅兜底。
- 验收：改绑定/角色后权限变更即时生效。（TASK-0005→0006→0007 构成前置链）

### TASK-0007（tasks/TASK-0007.md，越权红线自动化测试，P0，已确认，预估 3，前置=TASK-0005+0006）

- 两条验收红线固化为自动化用例：跨厂越权（数据类空/详情类 403）；scope 外中台拉树只返回授权子树；另含未绑部门 fail-closed、仅本人语义（时序空集）。
- 技术要点：每个查询接口（含对外 API）必须有越权用例（架构风险防法）；用例随 CI 跑。
- 实施步骤：测试夹具（两厂两账号+中台 appKey）→ 红线用例集 → CI 接入。
- 验收：红线两条全绿；上线前越权专项测试通过（架构验收）。验收命令：backend 权限测试套件（工程初始化后回填）。

### conventions.md 中与数据可见性相关的约束行

- 第 3 行（总则）：「跨 FEAT 必须一致的约束：鉴权、**数据可见性**、异常口径、导出一致性、枚举唯一定义点。」——把数据可见性列为跨 FEAT 一致性域。

## 四、给 brief 起草者的开放点（只列不裁决）

1. **子树展开上限无成文数值**：FEAT-0002 写「超限=子树展开上限（ADR 留痕）」，但详细设计 §4.1 步骤 4（p27）只写「展开全部后代实例」，未给上限阈值与超限行为（截断/报错/降级）。
2. **空结果与 403 的接口级划分清单缺失**：p27 红线说「按接口约定二选一并全组统一，推荐数据不存在类查询返回空、详情类返回 403」；REQ-0002/TC-0002 已定版为「列表/曲线类空、详情类 403」，但「哪些接口算详情类」两处均未枚举，brief 需给出清单或判定规则。
3. **仅本人的适用对象范围未成文**：p4 §0.2 与 p27 步骤 2 说「管理面列表场景改走 create_by」，REQ-0002（TD-0044）定版为「仅配置类对象按 create_by 生效」；「配置类对象」的具体接口集合未列出。
4. **多角色并集时 scope=4 的合并语义未写**：并集的其他成分是部门集合，仅本人的产出是 create_by 集合/空集，两种维度如何合并 p27/p4 均未说明。
5. **缓存失效粒度与「角色版本」来源未细化**：p27 步骤 6 只写按 (user_id, 角色版本) 缓存 + 变更时主动失效「相关缓存」；框架 sys_role 表无版本字段的说明、部门/绑定变更时失效范围（单用户还是全量）未定（TASK-0006 也只写了事件机制二选一）。
6. **sys_role 系列表租户隔离方式二选一未拍板**：p5 §0.3 改造三写「加 tenant_id（或经主表间接隔离，评审时二选一并全库统一）」，PDF 推荐直接加字段但未定版。
7. **中台 scope 的 JSON 结构无示例**：p18 §1.10 scope 为「实例 id/编码数组（含子树标记）」，子树标记的具体格式未定义；p27 §4.2 中台「与上相同的子树展开」如何复用步骤 4 也未写明。
8. **点位双条件 OR 的 NULL 边界**：p27 步骤 5 点位查询「dept_id 命中 OR bound_instance_id IN (可见集合)」，两字段皆空的点位行如何归类（对应 REQ-0002 未绑部门 fail-closed 兜底）在 SQL 层的表达未写明。
9. **TDengine 标签命名不一致**：p27 步骤 5 写「instance_code/dept 标签」，p19 §2.2 超级表标签实际名为 `instance_key` 与 `dept_id`，brief 引用时需统一叫法。
10. **dept_id「必填」与 DDL nullable 的口径差**：p10 §1.5 说工厂/车间级节点 dept_id 必填，p31 DDL 中该列为 `DEFAULT NULL`（无 NOT NULL）——必填是服务层校验口径，brief 需注明实现位置。
