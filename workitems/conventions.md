# 通用规范（CONV）

跨 FEAT 必须一致的约束：鉴权、数据可见性、异常口径、导出一致性、枚举唯一定义点。
条目一行一条，格式 `- **CONV-01** <一句话约束>`；编号取文件内 max+1。
REQ / FEAT / TASK / TC 正文用 `（CONV-01）` 引用。

## 通用规范

- **CONV-01** 业务数据字典（iot_data_dict，业务数据编码唯一来源）与框架系统枚举字典（sys_dict，下拉枚举）是两类字典，不得互相承载、不得混用。（ADR-0003）
- **CONV-02** 质量码数值枚举 0-10 为唯一存储口径：0 正常、1 超上限、2 超下限、3 断线/超时补标、4 设备异常值、5 手工补录、6 计算失败、7 汇总不完整、8 突变待核查、9 跨周期用量、10 比对偏差待核查（双给派生值与直报值偏差超阈值，原值不删、计入完整度缺失）；产品文本码映射 GOOD→0、OVER_RANGE→1/2、STALE/OFFLINE→3、JUMP→8、MANUAL→5；CALC_ERR 不落时序行（归 iot_calc_log）。（ADR-0009、ADR-0010）
- **CONV-03** 三份冻结契约（统一消息模型、配置快照 Schema、TDengine 超级表结构）冻结后第一批接入方可进入联调；契约变更必须升版本并通知各系统，冻结前不联调。（ADR-0009，TD-0046）
- **CONV-04** 分期遗留项统一登记于 `docs/workitems/phase2-backlog.md`：REQ 非目标中每写一条「二期/三期」，必须同步登记进该清单（REQ 转正前完成，漏登即回写）；一期收口验收（REQ-0032）须核对清单后移交二期计划，核对未完成不得收口；二期/三期启动时该清单为 intake 固定输入。（ADR-0012）
