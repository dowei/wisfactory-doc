名称：AlarmTimeoutScanner 裸 int 构造器致后端 dev 启动失败
所属模块：管理系统（Java）
相关功能：FEAT-0020
测试用例：不适用：启动类缺陷（Spring 上下文装配，单测直接 new 构造器不覆盖）
状态：已完成
关联任务：TASK-0090
优先级：P1
问题现象：`mvn spring-boot:run -pl ot-admin`（dev）启动失败：`APPLICATION FAILED TO START — Parameter 2 of constructor in net.otlab.admin.module.iot.alarm.scheduler.AlarmTimeoutScanner required a bean of type 'int' that could not be found`。8098 无监听，前端界面测试无法进行。
预期行为：后端 dev 正常启动、8098 可访问；timeoutSeconds 由配置 `ot.alarm.data-timeout-scan-seconds`（默认 300）注入。
实际行为：`AlarmTimeoutScanner`（TASK-0062 交付，@Component）构造器第三参数 `int timeoutSeconds` 未加 @Value，Spring 无 int bean 可注入 → 启动失败。同类 InspectResultStore/NoticeOutboxNotifier 无 @Component、经 @Bean 方法注入（有 @Value），不受影响。
复现步骤：1. `cd backend && OT_TDENGINE_BASE_URL=... mvn spring-boot:run -pl ot-admin`；2. 观察 test-compile 通过后 Spring 上下文启动报 Parameter 2 required a bean of type 'int'；3. curl 8098 = 000。
严重程度：严重（阻断整个后端启动/界面测试）
根因分析：TASK-0062 的 `AlarmTimeoutScanner.java:45-47` 构造器 `int timeoutSeconds` 漏 `@Value("${ot.alarm.data-timeout-scan-seconds:300}")`；单测 `AlarmTimeoutScannerTest` 直接 `new AlarmTimeoutScanner(...)` 传参绕开 Spring 装配，故 2513/2558/2613 全量单测绿但启动炸。对照 AlarmConfig 的 @Bean 方法用 @Value 注入 String targetRole 正确。
修复方案：构造器第三参数加 `@Value("${ot.alarm.data-timeout-scan-seconds:300}") int timeoutSeconds`（import org.springframework.beans.factory.annotation.Value）；加一条 Spring 上下文装配测试（@SpringBootTest 或 ApplicationContextRunner 断言该 bean 可创建），确保启动类缺陷被覆盖。微改 TASK-0090 承载。
完成时间：2026-11-25
验证结果：TASK-0090 微改闭合（提交 abad464e）——AlarmTimeoutScanner 构造器第三参数加 @Value("${ot.alarm.data-timeout-scan-seconds:300}")；新增 AlarmTimeoutScannerContextTest（ApplicationContextRunner 装配断言，旧版必红）。验证：`mvn -pl ot-admin test` 2614 tests/0F0E（2613 基线 +1，既有零回归）BUILD SUCCESS；启动实测 `Started OtAdminApplication in 12.166 seconds` + curl 8098 = **HTTP 200**（后端进程保留供界面测试）；前端 8099 = 200、Vite 代理 /api→8098 连通。收尾 LOG-0082。
