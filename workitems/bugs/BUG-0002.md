名称：TDengine 子表名转义映射不单射致不同点位编码写入同子表
状态：已完成
创建时间：2026-11-22 01:21:07
创建者：coordinator
所属模块：采集接入（Go）
相关功能：FEAT-0009
测试用例：TC-0023
关联任务：TASK-0073；TASK-0074
优先级：P1
问题现象：TASK-0073 修订轮引入的 childTable 确定性映射（escapeIdentifier：非 [A-Za-z0-9_] 字节转义为 `_XX`，恒等集含下划线本身）在契约合法的 pointCode 域上不单射——评审探针实测 `F01-WS01`（连字符转义为 `_2d` 得 `F01_2dWS01`）与字面编码 `F01_2dWS01_2aad8c0256245aa0` 映射到同一子表名；tenant_code 编码域同理（两租户同库口诀「每租户一库 iot_<tenant>」可被破坏）。
预期行为：任何两个不同的契约合法 pointCode（快照 Schema 只约束 maxLength 96、无字符集约束）映射到不同子表名；不同租户编码映射到不同库名（映射在合法域上单射）。
实际行为：不同 pointCode 可得到相同子表名；真 TDengine 接线（TASK-0029）后同子表 TAG point_code 不同将导致写冲突或不同点位数据混写；租户域同理。
复现步骤：1. cd ingest；2. 运行评审探针：对 pointCode `F01-WS01` 与 `F01_2dWS01_2aad8c0256245aa0` 分别调用 tdengine 包的 childTable 映射函数；3. 观察两者返回同一子表名（评审报告 TASK-0073-review.md 复评节 N1 实测）。
严重程度：严重（内核期假执行器无实害，TASK-0029 真执行器接线前必须闭合）
根因分析：转义集（`_` + 十六进制字节）与恒等集（`_` 原样保留）重叠——被转义字符的转义结果 `_XX` 本身是另一条合法编码的原样形态，构造性碰撞；映射未把 `_` 本身纳入转义，域内无单射保证。
修复方案：转义集定长化——把 `_` 本身纳入转义（如 `_5f`），使所有非安全字节与 `_` 都有唯一展开，映射在契约合法域上单射；补两条断言进 TC-0023：点位域单射性（含探针对）与租户域单射性；保留超长截断 + 哈希后缀但截断必须在转义后进行以保单射（评审报告已给同方向）。
