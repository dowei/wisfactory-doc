名称：未认证失败请求触发 OperateLog 写库撞 user_id 非空约束
所属模块：管理系统（Java）
相关功能：FEAT-0001
测试用例：TC-0024
关联任务：TASK-0075
优先级：P2
问题现象：未认证态触发带 @OperateLog 的失败请求（如 prod /auth/login/test 拒绝、登录失败路径）时，异步操作日志写入报 ERROR：`操作日志写入失败 … Field 'user_id' doesn't have a default value`——审计日志丢失，仅 ERROR 留痕。
预期行为：认证失败的请求（恰是审计最该记录的操作尝试）应留下操作日志：user_id 允许为空（记录尝试上下文），或以明确的系统占位身份落库；审计完整性不受认证态影响（REQ-0034 依赖 sys_operate_log 承载「谁调了接口」）。
实际行为：OperateLog 切面从当前会话取 user_id，未认证态为 null，INSERT 撞 sys_operate_log.user_id NOT NULL 约束 → 写入失败丢弃。
复现步骤：
1. prod 档启动（TASK-0009 报告验收 4 命令口径）
2. POST /auth/login/test（dev-only 接口在 prod 被拒，未认证态触发 @OperateLog）
3. 观察应用日志：出现「操作日志写入失败 … Field 'user_id' doesn't have a default value」（TASK-0009 报告验收 4 P4 实测复现，2026-11-22 01:57:31）
严重程度：一般
根因分析：OperateLog 切面（ot-core @OperateLog AOP + 异步线程池）在请求线程捕获操作上下文时，user_id 取自当前登录会话；未认证态为 null 直接进入 INSERT。sys_operate_log.user_id 列 NOT NULL 无默认值（01_base.sql）。历史暴露原因：正常使用中带 @OperateLog 的端点都在认证之后，仅认证失败路径可触达——TASK-0002/0009 的 prod 冒烟 P4 步骤首次踩中。
修复方案：① sys_operate_log.user_id 改 NULL 可空（增量脚本，information_schema 判存幂等）；② OperateLog 切面/实体对未认证态以 null user_id 落库并尽力记录尝试上下文（登录失败场景记 username 尝试值——切面现有字段能取到则记，取不到不造数）；③ 补红转绿测试：未认证态操作日志成功落库且 user_id 为 null。落点 TASK-0075（独立微改 bug 修复）。
完成时间：2026-11-22
验证结果：TASK-0075 修复提交 9754e0e。先红：prod /auth/login/test → `Field 'user_id' doesn't have a default value` + sys_operate_log 零新增（与 BUG-0003 复现同款）；后绿：同请求落库 user_id=NULL、user_name=probeUser 尝试值、无写库失败 ERROR；认证态回归 user_id=1 既有行为不变。关键修复口径：报错 SQL 列清单实证 MP NOT_NULL 策略省略 null 列——三列（user_id/user_type/user_name）一起可空化（增量脚本幂等，01_base 不改）。全量 1233 例 0 失败；加严评审两项证据独立复核一致（0 Critical/Important，4 Minor 记 deferred）。TC-0024 回归口径满足。
