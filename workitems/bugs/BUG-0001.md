名称：application-prod.yml 顶层 ot 键重复致 prod 档启动失败
所属模块：管理系统（Java）
相关功能：FEAT-0001
测试用例：TC-0022
关联任务：TASK-0072
优先级：P1
问题现象：按 TASK-0001 验收 4 原命令以 prod 档启动打包 jar（java -jar ot-admin-1.0.0.jar --spring.profiles.active=prod）时，Spring Boot 启动即失败退出，日志报 YAML 解析错误。
预期行为：prod 档打包产物用环境变量提供数据源/Redis/密钥后可直接启动（框架既有约定：prod 档真实启动是部署/配置类任务的验收门，L1-execute §6）。
实际行为：snakeyaml 严格模式解析 application-prod.yml 失败——`found duplicate key ot in 'reader', line 125, column 1`，Application run failed，任何 prod 实例无法启动。缺陷先于本 bug 发现时点存在（BASE 35d22f6 即如此，文件最后改动是 4b91219）。
复现步骤：
1. cd backend && mvn clean package -DskipTests
2. DB_HOST=localhost DB_PORT=3307 DB_NAME=ot_wisfactory DB_USERNAME=root DB_PASSWORD=root REDIS_HOST=localhost SM4_KEY=<dev默认值> CRYPTO_DATA_KEY=<dev默认值> CRYPTO_INDEX_KEY=<dev默认值> java -jar ot-admin/target/ot-admin-1.0.0.jar --spring.profiles.active=prod
3. 观察：启动日志报 found duplicate key ot（line 125），进程退出；修复后同命令应 Started OtAdminApplication 无 ERROR。
严重程度：严重
根因分析：backend/ot-admin/src/main/resources/application-prod.yml 顶层键 `ot:` 出现两次（94 行 ot.crypto/desensitize 段、125 行 ot.redisson/ip/mail 段）。Spring Boot 4 携带的 snakeyaml 对重复键直接抛异常；dev 档未触发是因为 application-dev.yml 无此问题且本地开发长期只跑 dev 档（试点 BUG-0003/0006 同类教训：dev 绿不代表 prod 能起）。
修复方案：结构性合并顶层重复键——删除 125 行的 `ot:`，将其下 redisson/ip/mail 子块原样并入 94 行的 `ot:` 块；不动任何键值语义，不改 SM4/CRYPTO 密钥的 fail-fast 约定（prod 密钥继续只从环境变量取）。合并后 yaml 语义校验 + prod 档打包启动冒烟（TASK-0072 承载）。
完成时间：2026-11-21
验证结果：TASK-0072 修复提交 27268a0。先红：修复前 prod 启动 EXIT=1 报 found duplicate key ot（line 125）；后绿：修复后打包 BUILD SUCCESS、prod 档启动 Started OtAdminApplication 启动段 ERROR=0、验证码+SM4 真实登录 200、GET /tenant/list 200、dev 档回归通过；全仓 application*.yml 全层级重复键扫描（含嵌套层）修复后全部 OK——除本缺陷外无同构问题。TC-0022 回归口径满足。
