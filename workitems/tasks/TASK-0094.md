任务描述：用户界面测试指出"模板只是基础，每个实例必须能自定义取值方式"。核查确认后端实例级写接口齐全：`PUT /iot/item/formula`（saveFormula）、`PUT /iot/item/rollup`（saveRollup）、`PUT /iot/item/bind`（已由 TASK-0092 接前端）、`PUT /iot/instance/{id}/items/{itemId}/params`（阈值，已接），且只有 locked=1 禁改。但前端 `item-api.ts` 零 saveFormula/saveRollup 调用，实例数据项抽屉每行只有「有效值/参数覆盖/绑定点位」，**公式型改公式、汇总型改汇总方式在界面上做不到**——与"模板为基础、实例可自定义"设计不符。本任务补齐这两个前端入口。**风险核对三行**：①改动范围=item-api.ts + 新公式/汇总编辑弹窗 + instance-item-drawer.vue + 测试，全 frontend；②引用 grep 结论=后端 IotDataItemController:122/:132 有 formula/rollup PUT（iot:item:edit），前端零调用，公式编辑器 iot-formula-editor.vue 已在模板弹窗使用可复用；③语义影响=仅接既有接口，不改后端语义（saveFormula 含语法/引用校验、source_type=2 清退 bind/rollup；saveRollup source_type=3 清退 formula/point）。
技术方案和要点：① item-api.ts 加 `saveFormula(instanceId,itemId,formula)` → PUT /iot/item/formula、`saveRollup(instanceId,itemId,rollupMethod)` → PUT /iot/item/rollup；② 新建实例数据项"取值编辑"弹窗（一个弹窗两模式：formula/rollup）——公式模式复用 `IotFormulaEditor`（ref-groups 按本实例数据项全键构造，参考模板弹窗 formulaRefGroups），汇总模式 SUM/AVG 单选（对齐 IotRollupRules.ALLOWED_METHODS）；③ instance-item-drawer.vue 每行按 sourceType 加操作按钮：公式项「编辑公式」、汇总项「编辑汇总」（v-privilege iot:item:edit），点击弹窗→保存→刷新清单；locked 项禁用按钮并提示（与实例锁口径一致）；④ 取值方式切换：如需把绑定项改成公式/汇总，提供"切换取值方式"入口（调对应接口即可，后端负责互斥清退）——若范围过大可只做同类型编辑，切换留演进位并在报告登记。
涉及文件：frontend/src/api/iot/item-api.ts + frontend/src/views/iot/instance/components/item-formula-edit-modal.vue（新）+ instance-item-drawer.vue + frontend/tests/unit/**；不改 backend/calc/ingest/contract。
